# Как ориентироваться в исходниках

Проект разделён по ответственности. При изменении поведения сначала найдите
слой, которому принадлежит правило, и меняйте соседние слои только на их
границах.

## Карта проекта

| Каталог / файл | Ответственность | Когда сюда идти |
| --- | --- | --- |
| `main/domain/load_controller.c` | Режимы CC/CV/CP/CR, ограничения, аварийные состояния, расчёт целевого тока и duty | Меняется физика или политика управления нагрузкой |
| `main/domain/pi_controller.c` | Общий PI-регулятор без знания о нагрузке и единицах измерения | Меняется математический алгоритм PI |
| `main/domain/load_limits.h` | Общие пределы и период управления | Меняются программные лимиты |
| `main/application/load_app.c` | Сценарии приложения: кнопки, меню, настройки, вызов измерения и регулятора | Меняется пользовательское поведение |
| `main/application/load_app.h` | События, порты адаптеров, публичное представление экрана и веб API | Меняется контракт между приложением и внешним кодом |
| `main/adapters/` | INA219, PWM LEDC, GPIO-кнопки, NVS, SH1107/LVGL и Wi-Fi/HTTP | Меняется работа конкретной периферии или интерфейсный рендеринг |
| `main/web_page.html` | HTML, CSS и JavaScript страницы устройства; встраивается в прошивку при сборке | Меняется внешний вид веб-страницы или её график |
| `main/platform/board_config.h` | Распиновка, адреса и начальные настройки платы | Используется другая разводка или плата |
| `main/app_main.c` | Сборка зависимостей и главный цикл FreeRTOS | Меняется запуск компонентов или расписание задач |
| `components/esp_lcd_sh1107/` | Локальный драйвер дисплея | Исправляется протокол или поведение SH1107 |
| `PROJECT_CONTEXT_AND_USER_MANUAL.txt` | Полное описание функций, ограничений и управления | Обновляется поведение, настройки или известные ограничения |

Сгенерированные каталоги `build/` и `managed_components/` не являются
исходниками приложения. Не правьте их для изменения поведения устройства.

## Поток данных

```text
buttons task ── app_event_t ─┐
                             v
INA219 adapter ─ measurement -> application/load_app -> domain/load_controller -> PWM adapter
                             |               |
                             v               v
                         app_view_t -> display adapter
                                    -> web snapshot API
```

`load_app_t` — внутреннее изменяемое состояние приложения. Экран и сервер
получают его копию `app_view_t`; они не должны менять состояние нагрузки.
Обращения к `load_app_t` из веб snapshot и основного цикла защищаются mutex в
`app_main.c`. Работа с LVGL защищается блокировкой LVGL port внутри
`display.c`.

## Типовые изменения

### Добавить правило режима или защиты

1. Определить правило в `domain/load_controller.c`.
2. Если появилось новое состояние ошибки или режим, обновить enum и все
   отображения этого enum: приложение, дисплей, JSON API и руководство.
3. Не помещать код GPIO, I²C, LEDC, LVGL или Wi-Fi в `domain/`.

### Добавить кнопку или пункт меню

1. Настроить GPIO в `platform/board_config.h` и опрос/антидребезг в
   `adapters/buttons.c`.
2. Передавать событие через `app_event_t`; переходы и действия реализовать в
   `application/load_app.c`.
3. Для нового пункта обновить `app_menu_item_t`, рендеринг в `display.c` и
   пользовательскую документацию.

### Добавить настройку оборудования

1. Добавить значение в `load_app_settings_t` и проверку диапазона в
   `application/load_app.c`.
2. Реализовать загрузку/сохранение ключа NVS в `adapters/settings_storage.c`.
3. Передавать применение настройки через порт приложения в соответствующий
   адаптер; экран редактирования остаётся в `display.c`.
4. Описать диапазон, шаг, управление и значение по умолчанию в руководстве.

### Изменить веб-страницу или API

`adapters/web_server.c` содержит настройку точки доступа и JSON обработчик
`/api/status`; разметка, стили и JavaScript находятся в `web_page.html`.
Показания берутся только через
`web_view_provider_t`, который отдаёт согласованный `app_view_t` snapshot.
Веб-обработчик не должен обращаться к датчику, PWM или внутреннему состоянию
контроллера напрямую.

### Перенести проект на другую плату

Сначала проверьте `platform/board_config.h`, `sdkconfig.defaults`, выбранную
цель ESP-IDF и таблицу разделов. Имена GPIO на плате и доступные периферийные
блоки должны соответствовать выбранному чипу.

## Правила, которые помогают не сломать разделение

- Зависимости направлены от адаптеров к application и domain; domain остаётся
  независимым от ESP-IDF.
- Application задаёт сценарии и вызывает аппаратные функции через
  `load_app_ports_t`.
- Адаптер измерителя переводит формат INA219 в `load_measurement_t`; правила
  режима не должны зависеть от регистров датчика.
- Общая структура для дисплея и веб API — `app_view_t`, а не `load_state_t`.
- Не вызывать LVGL из application или domain. Все операции с UI остаются в
  `adapters/display.c`.
- После изменения пользовательского поведения синхронно обновлять этот файл,
  `README.md` и подробный `PROJECT_CONTEXT_AND_USER_MANUAL.txt`.

## Сборка

Из корня проекта в окружении ESP-IDF:

```bash
idf.py -B build -DIDF_TARGET=esp32c3 build
```

Основной список исходников компонента находится в `main/CMakeLists.txt`.
